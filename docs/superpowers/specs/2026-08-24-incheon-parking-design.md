# 인천공항 주차 가용면수 수집·시각화 — 설계

작성일: 2026-08-24

## 1. 목적

인천국제공항의 주차 가용 면수를 주기적으로 수집·적재하고, 웹에서 다음 두 가지를
보여준다.

1. **현재 가용 현황** — 지금 어디에 몇 자리 남았는지
2. **시간에 따른 변화** — (a) 지정 기간의 실측 추이, (b) 요일×시간대 평균 패턴

공공 API가 당일 데이터만 제공하므로, 과거 이력은 직접 적재하는 것 외에 방법이 없다.
이 시스템의 존재 이유가 그것이다.

## 2. 데이터 출처

| 항목 | 값 |
|---|---|
| 데이터셋 | 인천국제공항공사_주차 정보 (data.go.kr/data/15095047/openapi.do) |
| 엔드포인트 | `https://apis.data.go.kr/B551177/StatusOfParking/getTrackingParking` |
| 요청 파라미터 | `serviceKey`, `numOfRows`, `pageNo`, `type=json` |
| 응답 필드 | `floor`(주차 구역), `parking`(주차 차량수), `parkingarea`(총 주차면수), `datetm`(갱신시각) |
| 승인 | 개발·운영 모두 자동승인 |
| 트래픽 | 개발계정 1,000/일 |

T1/T2 전 주차장이 한 번의 호출로 모두 반환된다. 주차장별 호출 불필요.
가용 면수는 API가 직접 주지 않으므로 `parkingarea - parking`으로 계산한다.

### 수집 주기

호출은 1틱당 1회. 개발계정 1,000/일 기준:

| 주기 | 일일 호출 | 판정 |
|---|---|---|
| 1분 | 1,440 | 초과 |
| 2분 | 720 | 여유 없음 |
| **5분** | **288** | 채택 |
| 10분 | 144 | 해상도 손해 |

**5분 주기를 채택한다.** 재시도 여유가 3배 남고, 시간대별 변화 그래프에 5분
해상도면 충분하다. 운영계정(자동승인)으로 올리면 1분도 가능하나 현재 불필요.

### 법적 검토 — 위치기반서비스 사업자 신고

**신고 대상이 아니다.** 근거:

- 2022-04-20 시행 개정 위치정보법은 "위치정보"를 전기통신설비로 **측위**된 정보로
  한정한다. 주차 잔여 면수는 측위값이 아니라 시설의 점유 현황 통계다.
- 특정 개인도, 이동성 있는 물건도 식별하지 않는다. 개인위치정보·사물위치정보 어느
  쪽에도 해당하지 않는다.

**설계 제약:** 브라우저 Geolocation API를 사용하지 않는다. 사용자 위치를 받는 순간
위치기반서비스사업 신고 대상이 되며(저장하지 않아도 동일), 미신고 시 3년 이하 징역
또는 3천만원 이하 벌금이다. 대상 공항이 인천 하나뿐이라 위치를 받을 이유가 없다.

## 3. 아키텍처

**단일 FastAPI 프로세스.** `lifespan`에서 asyncio 수집 루프를 띄우고, 같은 프로세스가
`/api/*`와 정적 파일을 서빙한다. 컨테이너 1개.

수집기를 분리하지 않는 이유: 분리의 유일한 실익은 "웹 재배포 시 수집이 안 끊긴다"인데,
끊겨야 5분 한 칸이고 그 칸은 그래프에 보이지 않는다.

개발 시 `uvicorn --reload`가 수집 루프를 중복 기동하지 않도록 가드를 둔다.

## 4. 데이터 모델

```sql
CREATE TABLE parking (
  ts       INTEGER NOT NULL,   -- API의 datetm → epoch seconds
  floor    TEXT    NOT NULL,   -- API 원문 그대로
  parked   INTEGER NOT NULL,
  capacity INTEGER NOT NULL,
  PRIMARY KEY (ts, floor)
) WITHOUT ROWID;
```

설계 근거:

- **가용 면수를 저장하지 않는다.** `capacity - parked`로 조회 시 계산한다. 파생값
  저장은 불일치만 만든다.
- **PK가 중복 방지 그 자체다.** `INSERT OR IGNORE`로 삽입하면, API의 `datetm`이 아직
  갱신되지 않았을 때 동일 행이라 조용히 무시된다. 별도 중복 체크 로직이 없다.
- **보존 무제한.** 5분 × 9행 = 2,592행/일 ≈ 연 95만 행 ≈ 30MB. 삭제 로직을 두지 않는다.
- WAL 모드를 켠다.

### 구역 그룹핑

`floor` 문자열 → `(terminal, kind)` 매핑을 **코드 내 dict**로 둔다. 값이 변하지 않으므로
테이블로 만들지 않는다.

데이터셋 설명상 구역은 9개다: 단기주차장 지하1층/지하2층/지상층, 장기주차장 P1~P4,
주차타워 P1/P2.

> **구현 시 확정 필요:** `floor` 필드의 정확한 원문 문자열과 각 구역의 터미널 소속은
> 실제 API 응답을 한 번 호출해 확인한 뒤 매핑 dict를 작성한다. 화면의 그룹 구성
> (터미널 × 단기/장기)은 그 결과에 맞춘다.

## 5. 조회 API

| 엔드포인트 | 용도 |
|---|---|
| `GET /api/current` | 최신 `ts`의 전 구역 + 그룹 합계 → 현황 카드 |
| `GET /api/series?from&to&group` | 실측 시계열 |
| `GET /api/pattern?group` | 요일×시간 평균 패턴 |

### 다운샘플링

30일 조회 시 그룹당 8,640포인트 × 4그룹 = 3.5만 포인트로 브라우저가 버벅인다.
**조회 기간이 3일을 초과하면 서버에서 1시간 버킷 평균**(`GROUP BY ts/3600`)으로 접고,
그 이하는 원시 해상도를 그대로 반환한다.

### 시간대 처리

`ts`는 epoch(UTC 기준 정수)로 저장하되, 요일×시간 패턴 쿼리는
`strftime('%w %H', ts, 'unixepoch', 'localtime')`로 KST 변환하여 묶는다.
컨테이너에 `TZ=Asia/Seoul`이 반드시 설정되어야 한다. 미설정 시 slim 이미지 기본값인
UTC로 계산되어 패턴이 9시간 밀린다.

## 6. 프론트엔드

정적 `index.html` 하나. 빌드 스텝 없음.

- 상단: 현재 가용 현황 카드 (그룹별)
- 하단: 탭 2개 — 실측 추이 / 요일×시간 패턴

차트 라이브러리는 구현 착수 시 `dataviz` 스킬을 참고해 확정한다.

요일×시간 패턴 탭은 데이터가 2~3주 쌓이기 전까지 빈약하다. 표본 수가 부족한 구간은
화면에 그 사실을 표시한다.

## 7. 오류 처리

- API 호출 실패 → 로그만 남기고 다음 틱으로 넘어간다. **재시도하지 않는다** — 5분 뒤에
  어차피 다음 호출이 온다.
- 트래픽 카운터를 두지 않는다. 288/1,000이라 셀 이유가 없다.
- `serviceKey`는 환경변수로 주입한다. 저장소에는 `.env.example`만 커밋한다.

## 8. 테스트

`test_app.py` 하나, 두 개의 테스트. 픽스처나 프레임워크를 쓰지 않는다.

1. API 응답 파싱 + 동일 `datetm` 재삽입이 무시되는지
2. 조회 기간에 따라 버킷팅 분기가 갈리는지

## 9. 배포

미니 PC의 도커에서 구동한다.

```yaml
services:
  parking:
    build: .
    restart: unless-stopped
    ports: ["8000:8000"]
    volumes: ["./data:/data"]
    environment:
      TZ: Asia/Seoul
      SERVICE_KEY: ${SERVICE_KEY}
      DB_PATH: /data/parking.db
```

- 베이스 이미지 `python:3.13-slim`. 멀티스테이지 빌드를 쓰지 않는다(순수 파이썬이라
  이득이 없다).
- DB는 named volume이 아닌 **bind mount(`./data`)**. `.db` 파일을 그대로 복사해 갈 수
  있게 하기 위함이다. 컨테이너가 root로 실행되어 호스트에 root 소유 파일이 생긴다.
- **`./data`는 로컬 디스크여야 한다.** NAS·네트워크 마운트에 두면 SQLite WAL이 깨진다.
- `restart: unless-stopped`가 크래시·재부팅 복구를 담당한다. 헬스체크를 넣지 않는다.
- 리버스 프록시·TLS 없음. 집 안에서 8000 포트로 접속하는 전제다.

## 11. 범위 밖

의도적으로 넣지 않는 것들:

- ORM, 마이그레이션 툴 — 스키마 변경이 실제로 필요해지면 그때 넣는다
- 사용자 인증
- 데이터 보존·삭제 정책
- 재시도 백오프
- 알림·임계치 기능
- 헬스체크, 리버스 프록시, TLS — 외부 노출이 필요해지면 Caddy를 붙인다
- 브라우저 Geolocation — 법적 사유로 영구 제외 (2절 참조)
