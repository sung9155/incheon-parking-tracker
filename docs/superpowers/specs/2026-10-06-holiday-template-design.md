# 연휴 위치 템플릿 — 예측 모델 설계 (2026-10-06)

## 목적

황금연휴의 주차 점유 급증을 하루 앞서 예측한다. 현행 모델(평소증감[평일·휴일×시각] + 순유출
보정)은 연휴 첫날을 번번이 놓쳤다. 추석(9/24~27)은 순유출 변수로 어느 정도 따라갔지만, 개천절
(10/3~5)은 순유출이 작았는데도(사흘 +2.1만 명) 주차가 추석보다 더 쌓여(+9,200대) 19~24h 오차가
단기 8.5~12.6%p로 돌아갔고, 12시간 만차 경보는 급증 첫날을 놓치고 마지막 날에 오경보를 냈다.

## 근거 (2026-10-06 워크포워드, 기점 9/13~10/6 매일 4회, 지평선 24h)

추석까지의 데이터로만 학습해 개천절을 예측한 결과. 19~24h MAE(%p), 현행 → 템플릿.

| 그룹 | 평시 | 추석(첫 연휴, 템플릿 없음) | 개천절(추석이 템플릿) |
|---|---|---|---|
| T1 단기 | 4.2 → 4.1 | 8.2 → 8.2 | 12.6 → 5.5 |
| T2 단기 | 4.4 → 4.3 | 7.2 → 7.2 | 8.5 → 3.8 |
| T1 장기 | 5.5 → 5.2 | 3.5 → 3.5 | 8.0 → 4.6 |
| T2 장기 | 3.4 → 3.3 | 1.5 → 1.5 | 5.4 → 2.7 |

12시간 만차 경보(단기, 예측 90% 이상) 개천절 기점: T1 적중 2·놓침 2·오경보 2 → 3·1·0,
T2 4·2·0 → 6·0·0. 첫 연휴(추석)는 템플릿이 없어 현행과 소수점까지 같다.

같이 시험하고 기각한 것: ① 체류 분포 변수 추가 — 장기에만 이득, T1 단기 평시 악화, 첫날 놓침
그대로. ② 체류 히스토그램 6칸 선형 보정 — 표본 밖에서 불안정(평시 오차 3배). ③ 진행 중인 연휴를
통합 셀로 쓰는 2단계 폴백 — 첫 연휴에서 과대(추석 +7.6%p). 예약 그룹은 템플릿을 쓰면 나빠진다.

## 설계

### 1. 달력 (`forecast.Calendar`)

`forecast.py`의 모든 함수가 받던 `off_dates: set`을 `Calendar` 하나로 바꾼다.

- `off`: 공휴일 ISO 날짜 집합 (지금의 off_dates).
- `pos`: 날짜 → 위치 코드. 전날 2, 첫날 3, 중간 4, 마지막 5, 다음날 6. 연휴 구간은 app.py의
  `golden_holidays()`(주말·공휴일이 이어진 구간)에서 온다. 전날·다음날은 연휴에 붙은 날이라 항상 평일이다.
- `run_end`: 날짜 → 그 연휴의 다음날 다음 자정(epoch). "끝난 연휴" 판정에 쓴다.
- `Calendar()`처럼 인자 없이 만들면 지금과 같은 달력(연휴 없음)이다. 테스트와 예약 그룹이 쓴다.

### 2. 셀 조회 (`forecast.py`)

- **기본 셀**은 지금과 같다: (휴일 여부, 시각). 연휴 날은 휴일 셀, 전날·다음날은 평일 셀. 연휴 안에서
  앞날 증감을 흡수해 뒷날에 쓰는 현행 동작이 그대로 남는다.
- **템플릿 셀**은 (위치, 시각). 학습 증감 중 **끝난 연휴**에 속한 시각만 들어간다. 끝난 연휴 =
  `run_end <= 학습 데이터 마지막 시각의 자정`. 진행 중인 연휴는 기여하지 않는다.
- 조회 순서: 템플릿 셀이 있으면 그것, 없으면 기본 셀, 그것도 없으면 None(적분 중단, 현행과 동일).
- 순유출 보정의 평소 기준(`mean_net`)은 지금처럼 평일·휴일 두 유형으로만 둔다.
- `Model`은 `mean_delta`(기본) 옆에 `tmpl_delta`(템플릿)를 하나 더 갖는다. 계수 `k`와 적분은 그대로.

### 3. 호출부 (`app.py`)

- `_forecast_inputs`가 `off` 대신 `Calendar`를 만들어 돌려준다. 범위는 학습창 60일 전부터 예고가
  닿는 이틀 뒤까지. 연휴 구간은 `golden_holidays()`를 직접 부른다(`/api/holidays`는 데이터 범위로
  잘라내므로 쓰지 않는다).
- 예약 그룹(`kind == "예약"`)에는 연휴 없는 `Calendar(off=...)`를 넘긴다.
- 현재 예측(`_live_forecast`)과 자정 기점 재현(`hindcast_day`·`_hindcast`)이 같은 경로를 타므로
  재현선도 자동으로 템플릿을 쓴다. 응답 형식과 프론트는 바뀌지 않는다.

### 4. 바뀌지 않는 것 / 범위 밖

- 지평선 24h, 상한 105%, 유의성 가드, 순유출 변수 — 그대로.
- 연휴가 아닌 급증(9/11~13 주말 T1 장기 100%)은 다루지 않는다. 체류 분포 기반 장기 보조 신호는
  후보로만 남긴다.
- 템플릿은 연휴 길이(3일/4일)를 구분하지 않는다. 중간 날은 모두 같은 셀이다. 표본이 쌓이면 재검토.

## 테스트

1. 끝난 연휴 하나가 있는 합성 세계에서 다음 연휴 첫날 예측이 템플릿 셀(그 연휴 첫날의 증감)을 따른다.
2. 진행 중인 첫 연휴(끝난 연휴 없음)의 예측은 `Calendar()`로 적합한 결과와 같다 — 폴백이 현행과 동일함.
3. `Calendar`가 3일 연휴에 전날·첫날·중간·마지막·다음날을 바르게 매기고 `run_end`가 다음날 다음 자정이다.
4. 기존 예측·재현·엔드포인트 테스트는 `Calendar` 서명으로 맞추고 전부 통과해야 한다.

## 배포와 검증

- 한글날 연휴(10/9 금~10/11 일, 전날 10/8)가 템플릿 둘(추석·개천절)로 치르는 첫 실전이다. **10/7까지**
  master 푸시·재배포.
- 10/12 이후 검증: 자정 기점 재현 vs 실측 일별 MAE, 12h 만차 경보 적중/놓침, 개천절 수치(위 표)와 비교.

## 위험

- 템플릿 표본이 연휴 1~2회뿐이라 특정 연휴의 특수성(개천절은 중국 국경절과 겹침)이 그대로 템플릿이
  된다. 연휴가 쌓이면 평균으로 희석된다.
- 학습창(60일) 밖으로 연휴가 밀려나면 템플릿이 비어 현행으로 돌아간다. 설날(2027-02-06~09)은 12/25·
  1/1 연휴가 창 안에 있어 괜찮다. 템플릿만 창보다 오래 보관하는 것은 표본이 쌓인 뒤 결정한다.
